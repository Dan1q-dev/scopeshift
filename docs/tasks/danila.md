# Данила: Backend, AI, engine и интеграция

Ветка: `feat/backend-simulation`. Прочитай `AGENTS.md`, `docs/PROJECT_BRIEF.md` и `docs/API_CONTRACT.md`.

Твои файлы: `src/types/**`, `src/lib/ai/**`, `src/lib/simulation/**`, `src/app/api/**`, `.github/workflows/**`, зависимости, сборка и серверное окружение. Ты координируешь изменения общих контрактов и слияния в `main`.

В `feat/backend-simulation` уже есть типы и схемы, публичный GET API, начальный сценарий, клиентский адаптер и детерминированный engine. `POST /api/negotiate` возвращает HTTP 200 для корректной истории с английским интерпретатором `rules-v1`. Live LLM и evaluator не подключены; до слияния PR `main` содержит старый каркас. Развивай существующие файлы; не создавай параллельный несовместимый каркас. Имена в `.env.example` зарезервированы. Подключение: `docs/BACKEND_INTEGRATION.md`.

## Следующие результаты

1. Сохранить общий HTTP-контракт при подключении frontend и evaluator.
2. Согласовать с Альбиной ограничения первого сценария и подключить `SimulationEvaluator` через `evaluation-port.ts`.
3. Соединить backend с UI Арсена и проверить весь пользовательский поток.
4. Перед подключением LLM добавить долговечное хранение проверенных интерпретаций ходов. Текущий session cache для этого не предназначен.
5. Подключить серверный provider с валидацией результата, затем проверить живой диалог и деплой.

## Правила реализации

- AI не изменяет экономику напрямую и не принимает недопустимые по сценарию условия.
- Предложение не считается соглашением. Принятое изменение применяется один раз.
- Сервер проверяет историю и восстанавливает состояние из доверенного исходного сценария. Не доверяет итогам, переданным браузером.
- Скрытые правила клиента и ключи остаются на сервере.
- Ошибки provider, валидации и повторной отправки возвращаются в согласованном формате.
- При неготовой интеграции возвращай честный статус или явно обозначенный режим разработки. Не имитируй работающий AI фиксированным успешным ответом.

## Интеграция

Принимай небольшие PR в `main`, сверяй совместимость контрактов и обновления lockfile. Сообщай команде об изменениях API и схем до слияния. Рабочие ветки после PR сохраняются.

Сначала добейся полного прохода одного сценария. Затем Replay с воспроизводимой историей и Change Order на основе реальных согласованных изменений. Голос и дополнительные возможности идут после этого.

## Проверка и деплой

Typecheck, lint, tests и build должны проходить локально и в CI. Проверяй смысловые сценарии вместе с Альбиной, интерфейс и ошибки вместе с Арсеном.

Настрой серверные переменные только в локальном окружении и деплое. После публикации проверь основной поток в инкогнито и отправь команде URL и известные ограничения. Перед первым сабмитом проверь состав команды и актуальные правила организаторов.
