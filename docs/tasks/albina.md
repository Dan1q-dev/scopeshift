## Первый результат

1. Первый сценарий Website Project с исходным scope: $1,500, 20 часов, 7 дней.
2. Три последовательных запроса: booking feature, ускорение срока, обмен части scope.
3. Для каждого запроса: сообщение клиента, трудозатраты, скрытые бюджетные и временные ограничения, допустимые исходы и встречные предложения.
4. Критерии оценки с конкретными доказательствами, а не субъективными процентами.
5. Таблица ожидаемых результатов для Данилы и содержательные тесты реализованного поведения.

Начни со сверки структуры сценария и evaluator с Данилой. Если для правила не хватает поля в контракте, предложи конкретное дополнение, прежде чем создавать собственный несовместимый формат.

## Оценка

Проверяй уточнение требований, управление scope, экономическую обоснованность, фиксацию соглашения и выполнимость обязательств. Каждый вывод должен ссылаться на действие пользователя и правило сценария.

Не делай единственно правильным ответом просьбу о доплате. Бесплатная небольшая правка, уточнение или равноценный обмен задач могут быть разумными. Отмечай факты, например дополнительные часы без компенсации; не делай выводов о личности пользователя.

## QA

Проверь принятые и отклоненные предложения, встречные условия, бесплатную работу, доплату, перенос срока, повторное соглашение, невыполнимые обязательства и неоднозначные сообщения. После появления frontend добавь Playwright-проверку основного потока.

Обязательно проверь нестандартные ответы: обмен новой функции на две старые, уточнение полей booking form, указание на уже включенную работу. Дефекты UI передавай Арсену, engine и API Даниле с шагами воспроизведения и ожидаемым результатом.

## Pitch

Подготовь английскую презентацию максимум на 10 слайдов и выступление на 5 минут: продукт, проблема, US-пользователь, интерактивное решение, демо, конкуренты, ценность и удержание, монетизация, рынок и предположения экономики, команда и видение.

Источники указывай рядом с данными. Цены, willingness to pay и прогнозы называй гипотезами, пока они не подтверждены. Сверь актуальные требования организаторов с капитаном. Готовность deck и PDF проверяется отдельно от готовности продукта.

## Готовность к первому PR

Сценарий соответствует общим типам, ожидаемые исходы описаны, критерии оценки объяснимы. Проверки проходят для реализованных модулей. В PR явно укажи зависимости от engine и перечень еще не реализованных тестовых случаев.
