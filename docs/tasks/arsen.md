# Арсен: Frontend и UX

Ветка: `feat/frontend-experience`. Перед работой прочитай `AGENTS.md`, `docs/PROJECT_BRIEF.md`, `docs/API_CONTRACT.md` и `src/types/scope.ts`.

Твои файлы: страницы лендинга, симуляции и результатов, `src/app/globals.css`, `src/components/**`, `src/lib/client/**`. Backend, engine, сценарии и общие типы меняет соответствующий владелец.

## Первый результат

Рабочий стол первого сценария, который можно соединить с backend без переделки моделей данных:

- Исходный договор, текущий scope, цена, часы, срок и эффективная ставка.
- История переписки, ввод произвольного текста, отправка сообщения.
- Явные состояния загрузки, ошибки, повторной отправки и завершения.
- Видимое различие между предложением и принятым соглашением.
- Итоговый экран с объяснимой обратной связью.

Каталог и публичный сценарий доступны через GET API. Используй готовый адаптер `src/lib/client/api.ts`: `getScenarios`, `getScenario`, `negotiate`, `ScopeShiftApiError`. PR #1 уже слит в `main`: корректная история переговоров возвращает HTTP 200 по прежнему контракту, engine использует ограниченный английский `rules-v1` без live LLM. Сохрани свою работу и подтяни `origin/main` в frontend-ветку. OpenAI-режим находится отдельно в `feat/backend-simulation` до следующего слияния. Evaluator пока возвращает пустые массивы. Порядок сообщений, retry и Replay описаны в `docs/BACKEND_INTEGRATION.md`. Fixtures помечай явно и не представляй как живой AI.

Для запуска ключ не нужен. Motion и shadcn/ui пока не установлены; согласуй нужные зависимости с Данилой до изменения `package.json` и lockfile.

## Следующие шаги

1. Профессиональный английский лендинг с понятным входом в демо.
2. Удобный responsive интерфейс симуляции и результатов.
3. После полного цикла: история изменений, Replay & Compare и Scope Diff.

В Replay меняй историю попытки и получай пересчитанный результат через согласованный backend. Расчеты денег и решения клиента остаются в engine.

## Готовность к первому PR

Основные экраны доступны, отправка сообщения подключается через единый клиентский модуль, состояния UI обработаны. Укажи, работает ли PR с fixtures или с backend. Проверь typecheck, lint, tests и build. PR направь в `main`, попроси Данилу об интеграции.

Вопросы к капитану перед изменением контрактов: какие данные доступны клиенту, как сохраняется история и как возвращаются ошибки. Референсы дизайна можно запросить, но они не должны блокировать рабочий основной поток.
