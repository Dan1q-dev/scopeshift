# Backend: подключение команды

PR #1 слит в `main`. Рабочий backend уже можно подключить в своей ветке: сохрани текущую работу, выполни `git fetch origin` и `git merge origin/main`.

GET API, общие типы и клиентский адаптер сохранены. Корректный `POST /api/negotiate` возвращает HTTP 200 с результатом engine. Frontend Арсена уже слит через PR #2. В main остается `rules-v1`; OpenAI-интеграция идет отдельным срезом. Evaluator и облачный деплой пока не подключены. Для rules ключ не нужен; интерпретатор понимает ограниченный набор явных английских формулировок и оставляет неясный ответ без изменения договора.

Для запуска backend в существующей копии с сохраненной текущей работой, оставаясь в своей ветке:

```sh
git fetch origin
git merge origin/main
npm ci
npm run dev
```

Если рабочая ветка еще не создана, сначала выбери ее по `docs/TEAM_QUICKSTART.md`. Арсен и Альбина продолжают работу в своих ветках и синхронизируются через PR в `main`. OpenAI подключается отдельно в `feat/backend-simulation`; этот раздел описывает уже слитый режим `rules-v1`. Серверная настройка OpenAI: [OPENAI_SETUP.md](OPENAI_SETUP.md).

## Арсену

- Используй `getScenarios`, `getScenario`, `negotiate` и `ScopeShiftApiError` из `src/lib/client/api.ts`.
- В версии с OpenAI адаптер сам инициализирует сессию через `GET /api/session` перед POST. Этот GET не вызывает модель; отдельный bootstrap в компонентах не нужен. JSON переговоров остается прежним.
- Первый запрос клиента берется из первого `PublicScenario.events`. В POST отправляй всю историю, включая новый ответ пользователя. `turnId` создавай один раз через `crypto.randomUUID()` и сохраняй для retry.
- Для совместимости с OpenAI отправляй по одному новому ходу за запрос и сохраняй cookie. Старый префикс должен уже быть обработан сервером в этой сессии; не отправляй сразу несколько новых ходов.
- Покажи все `turns`, включая последний `clientReply`, затем найди новое событие по `currentEventId`. Отдельного поля следующего сообщения в ответе нет.
- `accepted` меняет договор. `counteroffered` содержит предложение клиента, договор пока прежний. Для принятия отправь новый ход текущего события, например `I accept your offer.`
- При `completed: true` покажи результат и отключи следующий ход. Деньги в API указаны в центах USD.
- Replay: оставь неизмененный префикс, обрежь старый суффикс и создай новые ID для всех его замен. Одинаковая история при retry пересчитывается с исходного договора без повторного начисления.
- Оценка пока pending с пустыми массивами. Не показывай произвольные баллы. Не называй `rules-v1` живым AI.

Формы HTTP и ошибки перечислены в [API-контракте](API_CONTRACT.md). Открытые файлы сценария не импортируются в browser bundle.

## Альбине

Точка подключения оценки: `src/lib/simulation/evaluation-port.ts`.

```ts
type SimulationEvaluator = (context: {
  scenario: Scenario;
  turns: readonly NegotiationTurn[];
  project: ProjectState;
  completed: boolean;
}) => EvaluationResult;
```

Данила передает evaluator третьим аргументом `negotiateHistory(scenario, history, evaluate)`. Ходы и проект передаются в evaluator как копии, чтобы оценка не меняла финансовый результат. По умолчанию все массивы оценки пусты.

Текущая модель ориентирована на три события начального сценария. Пустой `availableScopeItems` означает запрос на ускорение срока. Capacity считается как общие часы / дни от начала договора; выполненная работа и прошедшее время не моделируются. Новый сценарий с другой механикой нужно заранее согласовать с Данилой.

В исходных правилах rush-события нет стратегии `free_change`: бесплатное ускорение отклоняется, даже если по часам выполнимо. Если это педагогически неверно, Альбина может осознанно добавить стратегию после сверки ожидаемого поведения. Backend не переписывает ее сценарий.

## Канонические примеры

Фразы ниже являются контрольными примерами ограниченного parser, а не универсальной поддержкой свободного диалога.

| Событие и ответ пользователя | Результат |
| --- | --- |
| Booking: `I can add booking for an extra $400 and two more days. Would that work?` | Accepted: $1,900, 26 ч, день 9, $73.08/ч |
| Booking: `I can add it for free with no change to the deadline.` | Accepted: $1,500, 26 ч, день 7, $57.69/ч |
| Booking: предложение $900 и двух дополнительных дней | Counteroffer $400, договор не меняется до принятия |
| Текущее booking-событие после counteroffer: `I accept your offer.` | Условия встречного предложения приняты |
| Любое событие: `Sure.` | Недостаточно условий, договор не меняется |

После первого платного booking-примера можно продолжить двумя ходами с новыми ID:

1. `earlier-delivery`: `I can deliver two days earlier for an extra $150.`
2. `scope-swap`: `Replace the portfolio gallery with testimonials at the same price and deadline.`

Итог такой ветки: $2,050, 26 часов, день 7, $78.85/ч, `completed: true`. Уточнения, отклоненные предложения и counteroffer сохраняют текущее событие; принятое соглашение и разрешенный отказ от запроса переводят к следующему.

## Повторная отправка и ограничения

Экономический результат строится чистым engine с исходного договора. В `rules` анонимная cookie дает дополнительную best-effort проверку конфликтов `turnId` и ограничение 30 запросов/минуту в памяти одного процесса. Срок сессии 60 минут, максимум 500 сессий и 256 fingerprints на сессию. Cache не хранит финансовое состояние или результаты LLM. Перезапуск, другой instance или новая cookie обходят эти best-effort ограничения.

В OpenAI-режиме используются подписанная cookie и локальные постоянные receipts проверенных ходов. Обработанный префикс не отправляется в LLM повторно; потерянная серверная история дает ошибку. Локальная файловая система не обеспечивает общий storage на Vercel, поэтому такой деплой OpenAI пока закрыт. Полный контракт настройки и ограничений: [OPENAI_SETUP.md](OPENAI_SETUP.md).

Успешный ответ помечен `X-ScopeShift-Interpreter: rules-v1`, `X-ScopeShift-Evaluation: pending`, меткой ревизии и `Cache-Control: no-store`. Payload ограничен 131072 байтами. Подробные HTTP-коды: [API-контракт](API_CONTRACT.md).

## Проверка

Обязательные команды: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. Для HTTP smoke запусти сервер и в другом терминале выполни:

```sh
node scripts/smoke-backend.mjs http://127.0.0.1:3000
```

Эти команды описывают процедуру проверки. Результаты текущего запуска капитан сообщает отдельно; наличие backend-среза не доказывает готовность пользовательского демо.
