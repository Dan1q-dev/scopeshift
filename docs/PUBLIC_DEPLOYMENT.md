## Сохранение и доступ

Receipts и проверенные снимки попыток живут в Postgres. UI сохраняет браузерный кэш и загружает серверную историю текущей подписанной сессии. `GET /api/attempts` выбирает до 20 последних измененных попыток, отдавая самые новые снимки в пределах JSON-лимита 3 MiB. Остальные строки остаются в БД.

Анонимная cookie действует 30 дней с создания; стабильный `SCOPESHIFT_SESSION_SECRET` сохраняет ее валидность между деплоями. Это срок доступа, а не политика удаления SQL-строк: автоматическое удаление истории через 30 дней не настроено. Потеря cookie, другой браузер или истечение сессии не восстанавливают старый доступ. Аккаунтов и переноса истории между устройствами нет.

Общая квота - 200 новых попыток OpenAI-вызова в день UTC, параметр `SCOPESHIFT_DAILY_AI_CALL_LIMIT`. Повтор сохраненного запроса и воспроизведение обработанного префикса не вызывают модель и не расходуют новую квоту. Новые ответы альтернативной ветки расходуют квоту как обычно. Неуспешная новая попытка тоже может ее расходовать. При исчерпании API возвращает 429 с `Retry-After` до полуночи UTC.

Неоднозначный сбой provider или процесса оставляет durable `pending` claim. Другой инстанс не перехватывает его и не запускает повторную интерпретацию автоматически. Для такого хода нужна новая попытка либо проверка оператором. Изменение модели или сценария требует новых попыток вместо переинтерпретации старых receipts.

## Обновление production

Деплой выполняется Vercel CLI из рабочей копии, связанной с существующим проектом `scopeshift`. Настройки находятся в `vercel.json`, production-секреты уже заданы в Vercel. Из связанной копии:

```powershell
vercel.cmd deploy --prod --yes --scope daniel-edens-projects
```

Для новой рабочей копии сначала свяжи ее с существующим проектом через `vercel link`, затем проверь выбранные scope и проект. Обычный Git push сам по себе в этой приемке не использовался как подтвержденный способ публикации; автоматический Git-деплой не заявляется.

Окружением управляет капитан. `scripts/configure-vercel-env.mjs` передает значения из игнорируемых локальных env-файлов и окружения в production-настройки, не выводя секреты. После изменения переменных нужен новый deployment: уже работающая версия не получает новые значения автоматически. Сохраняй тот же session secret и ту же production-БД для непрерывной анонимной истории.

Перед публикацией изменения схемы проверь версионированный SQL на дочерней ветке БД и примени его прямым подключением. Инструкция: [OPENAI_SETUP.md](OPENAI_SETUP.md). Env-файлы, `.scopeshift` и локальные артефакты исключены и из Git, и из Vercel upload.

Проверка опубликованного потока:

```sh
node scripts/smoke-persistence.mjs https://scopeshift.vercel.app
```

Этот запуск делает настоящие AI-вызовы и сохраняет синтетическую cookie и историю в игнорируемом `.scopeshift/persistence-smoke.json`. После нового deployment той же версии можно повторить сохраненную ветку без новых AI-вызовов:

```sh
node scripts/smoke-persistence.mjs https://scopeshift.vercel.app --retry
```

Контракты и ошибки описаны в [API_CONTRACT.md](API_CONTRACT.md). Исторический локальный проход до публикации сохранен в [DEMO_READINESS.md](DEMO_READINESS.md).
