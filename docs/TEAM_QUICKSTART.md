# Короткая инструкция команде

Репозиторий: https://github.com/Dan1q-dev/scopeshift

GitHub-аккаунты команды: Данила `Dan1q-dev`, Арсен `arsengabdrahmanov7-ux`, Альбина `albina2nik-crypto`.

Сначала примите приглашение GitHub: право записи появляется после принятия. Для чтения публичного репозитория приглашение не требуется. Установите Git и Node.js 22 (>=22.12, в пределах ветки 22.x) с npm.

## Первый запуск

```sh
git clone https://github.com/Dan1q-dev/scopeshift.git
cd scopeshift
git fetch origin
```

Затем выполните только команду своего участника:

| Участник | Команда |
| --- | --- |
| Данила | `git switch --track origin/feat/backend-simulation` |
| Арсен | `git switch --track origin/feat/frontend-experience` |
| Альбина | `git switch --track origin/feat/scenarios-quality` |

```sh
npm ci
npm run dev
```

Приложение открывается по адресу `http://localhost:3000`. Сначала прочитайте `AGENTS.md`, `docs/PROJECT_BRIEF.md`, `docs/API_CONTRACT.md` и свое задание в `docs/tasks/`.

Ключ для запуска не нужен. `.env.example` содержит зарезервированные имена и пока не используется. В `feat/backend-simulation` добавлены engine и переговоры с HTTP 200 по прежнему контракту; live LLM и evaluator не подключены. До слияния PR `main` остается прежним каркасом. После слияния подтяните `origin/main` в свои ветки. Подключение: `docs/BACKEND_INTEGRATION.md`.

## Как работать

1. Работайте в своей ветке и в своей зоне файлов из `AGENTS.md`.
2. Перед новой задачей проверьте `git status`. Сохраните текущую работу коммитом, затем выполните `git fetch origin` и `git merge origin/main`.
3. Если изменился lockfile, выполните `npm ci` заново.
4. Перед PR выполните `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
5. Добавьте в коммит только свои файлы, проверьте `git diff --cached`, сделайте коммит и `git push`.
6. Откройте PR из своей ветки в `main`. Напишите, что готово, как проверено и что нужно от другого участника. Сливает Данила.

При конфликте в чужих файлах или изменении общих типов подключите капитана. Не используйте force push. Не удаляйте рабочие ветки после слияния, они нужны для следующего этапа.
