Этот отчет фиксирует локальную проверку до публикации. Актуальный публичный URL и подтверждение постоянного хранения находятся в [PUBLIC_DEPLOYMENT.md](PUBLIC_DEPLOYMENT.md).

PR #3 слит в `main`, merge commit `f4bb03824ff6be77fd6c50429b62e9de7c772fb7`. Проверка выполнена в настоящем Chrome через интерфейс локального production-сервера Next.js с OpenAI. Это проверка локального приложения, не опубликованного сайта.

## Пройденный сценарий

1. Лендинг открывает рабочий стол без регистрации. Исходный договор: $1,500, 20h, 7 дней, $75.00/h.
2. Вопрос о полях формы и ручном/автоматическом подтверждении получает содержательное пояснение. Неопределенные требования прямо названы; договор не меняется.
3. Предложение добавить booking за $900 и два дня получает контроффер $400. До принятия остаются $1,500 / 20h / 7 дней.
4. `I accept your offer.` применяет booking: $1,900 / 26h / 9 дней, $73.08/h.
5. Срочность за $150 возвращает срок к 7 дням: $2,050 / 26h, $78.85/h.
6. Замена gallery на testimonials при прежней цене и сроке завершает все три события. В scope видны удаленная gallery и добавленные booking/testimonials.
7. Replay под решением о срочности создает вторую попытку и сохраняет предыдущие ходы: снова $1,900 / 26h / 9 дней. Отказ от срочности и тот же обмен завершают альтернативу без изменения этих цифр.
8. Results сравнивает обе завершенные попытки: $78.85/h и $73.08/h. Оценка содержит критерии, наблюдения и советы. Уточнение оценивается как вопрос, а не как доказанное разрешение требований.
9. Обновление Results сохраняет обе попытки. `Open this attempt` открывает выбранную первую попытку с ее историей и результатом.
10. При намеренно остановленном локальном сервере отправка показывает понятную ошибку сети и `Send again`. После запуска сервера повтор успешно выполняется.
11. В этой третьей попытке `Replace contact form and portfolio gallery with booking at the same price and deadline.` дает $1,500 / 18h / 7 дней, $83.33/h. Обе удаленные задачи отражены в договоре. Обновление страницы сохраняет результат; следующий ход проходит после перезапуска сервера.
12. На мобильном viewport 390x844 рабочий стол и карточки результатов складываются в одну колонку. DOM-проверка показала одинаковую ширину документа и содержимого, без горизонтального переполнения. Временный viewport сброшен.

## Исправления после прохода

В ветке `codex/demo-readiness` исправлены найденные проблемы интерфейса:

- Плашка больше не утверждает `rules-v1` при включенном OpenAI. Режим берется из `/api/session`; текст разделяет интерпретацию OpenAI и решения/реплики engine. Исправленная плашка проверена в браузере.
- Results недоступен во время отправки. Это закрывает обнаруженную в исходниках возможность открыть устаревшие результаты до завершения запроса. Disabled-состояние проверено в браузере; исходная гонка отдельно не воспроизводилась.
- Инициализация разделяет один незавершенный session bootstrap между потребителями; отмена одного не прерывает идентификацию другого. Запросы отменяются при уходе со страницы.
- Foundation E2E обновлен под актуальный лендинг и публичный сценарий. Автоматический Playwright E2E в этом проходе не запускался; браузерная приемка выполнена через UI.
- Убраны устаревшие статусы из брифа и инструкции OpenAI.

После исправлений прошли `npm run typecheck`, `npm run lint`, `npm test` (111 тестов в 14 файлах), `npm run build`. Production-сервер перезапущен из новой сборки; повтор, сохранение, режим, busy-состояние и мобильный вид проверены на ней. Полное первое прохождение и Replay были проверены на слитом PR #3 до этих небольших исправлений.

Локальные скриншоты находятся в игнорируемом `artifacts/demo-review/`: `results-desktop.jpg`, `results-mobile.jpg`, `workspace-mobile.jpg`. Они не содержат ключей или реальных клиентских данных и не отправляются в Git.

## Что осталось до сдачи

1. **Данила: публичный запуск и приемка опубликованного URL.** Сейчас OpenAI хранит receipts на постоянной локальной файловой системе. Для Vercel нужен адаптер общего постоянного хранилища; текущая конфигурация блокирует OpenAI на Vercel. Другой вариант демо - постоянный Node-сервер с сохраняемым каталогом. Нужен полный проход опубликованной версии без входа.
2. **Альбина: согласовать и интегрировать существующий pitch.** В `origin/feat/scenarios-quality` на `80ceef592eba11ada40ce8dfefd37f4176b1464d` уже есть PDF и исходник `pitch/storyline.md`. В `main` их пока нет. По текстовому исходнику требуется заменить старые +4h booking и $1,800/24h на текущие исходы, согласовать состав обмена, цену подписки ($12 в pitch против $9 на лендинге) и роль LLM. Бинарный PDF в этой проверке не открывался и его верстка не подтверждалась. После правок нужно пересобрать PDF, добавить production URL и перенести материалы в `main`.
3. **Арсен: полировка обратной связи.** Доказательства полезны, но сейчас показывают технические ID соглашений и многословные наблюдения. Их можно сделать компактнее для выступления. Это не блокирует проверенный цикл.

## Границы готовности

- OpenAI интерпретирует свободный текст. Реплики клиента формирует engine из решений и фактов сценария; свободного генеративного собеседника пока нет.
- Поведение бронирования и источник слотов в сценарии определены не полностью. Уточнение честно показывает эти пробелы.
- OpenAI cookie действует один час, а сохраненные попытки живут дольше. При истечении сессии продолжение старой ветки может быть отклонено; нужна новая попытка. Уже сохраненные Results доступны.
- Ошибка сети проверена с остановленным сервером до обработки запроса. Потеря ответа после оплаченного вызова в браузере не моделировалась; retry/receipts отдельно покрыты backend-тестами и предыдущим HTTP smoke.
- Локальные проверки не означают успешный remote CI или готовый deployment.

Инженерная оценка: функциональное локальное демо около 90%, комплект для сдачи около 75%. Это оценка оставшейся работы, не вычисленный балл качества. Главные незавершенные результаты: публичный URL с проверенным OpenAI и согласованный pitch в общей ветке.
